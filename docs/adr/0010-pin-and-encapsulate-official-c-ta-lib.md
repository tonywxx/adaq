# Pin and encapsulate official C TA-Lib

ADAQ's host-owned `adaq-indicator-engine@1.0.0` uses the official C TA-Lib v0.7.1 source release pinned by SHA-256, vendored in the repository, and statically linked behind a Tauri-independent `adaq-indicator-engine` crate. That crate exclusively owns unsafe FFI and error conversion and uses a process-wide `OnceLock` for one single-threaded initialization that explicitly restores the v0.7.1 default unstable periods and candlestick settings before concurrent evaluation begins; failure is sticky, and neither Strategies, Plans, nor Runs may mutate or retry initialization. Lightweight Engine handles share the initialized library, immutable compiled definitions are safe to share, and each evaluation owns its parameter holders and buffers so TA functions may run concurrently without a global computation lock. ADAQ deliberately does not call `TA_Shutdown` from handle destruction or normal desktop shutdown, avoiding use-after-shutdown and global destructor ordering while allowing the operating system to reclaim process resources; initialization-isolation tests use separate processes. Those defaults are part of the Indicator Engine version and all lookbacks, Warmup, and golden vectors. A target/compiler/flags build fingerprint forms the separate Engine Build ID. ADAQ does not depend on a system TA-Lib installation, ship a runtime shared-library dependency, or download TA-Lib during build or execution. TA-Lib remains outside Component SDKs, WIT contracts, and `.adaq` packages, so Strategy Components receive only frozen Feature Slots and do not require recompilation when the host changes Indicator Engine implementations.
