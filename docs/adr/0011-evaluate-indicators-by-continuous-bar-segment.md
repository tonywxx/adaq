# Evaluate Indicators by Continuous Bar Segment

M5 exposes a concrete host-side Indicator Engine that compiles normalized Indicator requests and evaluates one Continuous Bar Segment at a time through TA-Lib's batch model. Results are fixed-order columns aligned to input Bar indexes, with absence permitted only during exact Warmup and finite scalars required thereafter. The Run Engine evaluates Built-ins once per segment, processes each stateful Factor over 4,096-Bar chunks while retaining only Plan-referenced outputs for the current chunk, joins Market, Built-in, and Factor values by Bar index and authoritative Slot order, suppresses Warmup or missing frames without advancing Strategy state, and invokes Strategy over at most 4,096 eligible Frames per call before mapping validated Target Exposures back to their Closed Bars. A fatal error ends the Run rather than returning a partial result as complete, and every Bar Gap rebuilds the analytical pipeline. Before allocation the host uses checked arithmetic and enforces fixed ceilings of 1,000,000 Closed Bars, 256 Feature Slots, 256 unique normalized Built-in requests, 64 Factor Instances, 64 declared outputs per Factor, 100,000 effective Warmup Bars, 16,777,216 Indicator output cells, and 1 MiB of canonical Plan JSON; Components cannot change these ceilings, and M5 adds no Manifest resource-limit schema. Every Factor output name is a unique lower-kebab-case identifier of at most 64 bytes, and every present row must match the complete declared count and order before the host retains only Plan-referenced values. Identical normalized Built-in requests or Factor outputs are computed once even when several Slots bind them. The boundary does not expose TA-Lib functions or state, add per-Indicator host methods, introduce a single-implementation trait, or provide a streaming API. A future non-authoritative realtime path may add a separate streaming adapter without changing historical Run semantics.
