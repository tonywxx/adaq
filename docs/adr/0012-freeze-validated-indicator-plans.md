# Freeze validated Indicator Plans

Before a Run, ADAQ resolves every Strategy Component-declared Feature Slot through one `validate_and_freeze` gate and produces a canonical, SHA-256-addressed Indicator Plan. M5 accepts exactly `manifestSchemaVersion: "1.0.0"` and `planSchemaVersion: "1.0.0"`; these versions are independent of Component, SDK, and Factor/Strategy ABI versions and are not range-negotiated. Strategy Manifests contain one authoritative ordered `featureSlots` array; each Slot source is exactly one raw `market` OHLCV field, Catalog-backed `builtin` request, or `external` dependency alias plus Factor output name. Market sources are limited to open, high, low, close, base volume, and quote volume, have zero Warmup, and are converted from authoritative Decimal values to finite analytical `f64` without entering TA-Lib; this gives Embedded Strategy logic explicit raw inputs without adding a full Bar ABI. M5 removes and rejects the experimental `inputNames` field instead of maintaining dual readers. Slot names are unique stable lower-kebab-case identifiers of at most 64 ASCII bytes; Manifest order is authoritative, becomes the dense zero-based runtime order, and cannot change within a Component version. Each required Slot carries one finite `f64` scalar; TA-Lib validates Built-in requests but the host never infers semantic compatibility between arbitrary scalar sources. A Built-in request parameter is either a typed literal or a direct reference to a parameter declared by the same Strategy: Integer literals are JSON integers, Real literals are decimal strings, and Enum literals are stable lower-kebab-case Catalog IDs. Omitted parameters use Catalog defaults, and freezing materializes every default, normalizes equivalent decimal spellings and Enum IDs, and rejects nulls, unknowns, type mismatches, extra values, and out-of-range values. M5 has no parameter expressions, conditions, or Slot-to-Slot references. Each unique lower-kebab-case dependency alias identifies one Factor Instance; the same Factor Component may appear under multiple aliases with different parameter bindings. The Component Lock resolves and locks each alias's exact Package, while the Indicator Plan freezes that Instance's normalized parameters, selected outputs, and Warmup. External Factor parameters use the same literal-or-Strategy-parameter binding model, and every Continuous Bar Segment recreates one Factor Instance per alias. After validation the existing Strategy WIT remains source-agnostic: the host creates the Strategy with only the exact ordered Slot names and parameters, then sends finite dense `f64` frames of the same length and order. The guest may bind names to indexes once but never receives Market, Indicator, Factor, or TA-Lib metadata; Warmup and missing inputs produce no Frame, and a Bar Gap creates a new Strategy Instance. The Plan freezes its schema version, Strategy Package hash, `adaq-indicator-catalog@1.0.0`, `adaq-indicator-engine@1.0.0`, TA-Lib `0.7.1`, Engine Build ID, normalized source inputs and parameters, output names, per-source and effective Warmup, ordered Slots, and hash while leaving Factor Package hashes to the Component Lock and Run-specific Instrument, Snapshot, allocation, and execution settings to their owning records. Its `planHash` is lowercase SHA-256 over RFC 8785 JCS bytes of the complete normalized Plan excluding the hash field itself; object keys are canonicalized, arrays preserve order, and loading always recomputes the hash. Validation rejects unsupported engines or schemas, Manifest mismatches, incomplete or extra bindings, invalid inputs, parameters, outputs or lookbacks, incompatible Factor metadata, resource-limit violations, and non-canonical hashes; no partial Plan can start a Run.
