# Version Component feature contracts semantically

Component SemVer treats any Feature Slot addition, removal, rename, reorder, source-kind or exact-source change, Parameter removal or type change, optional-to-required change, or Factor output removal, rename, or reorder as a major change because it breaks the dense runtime contract. Adding an optional Parameter with a default, appending a Factor output, or adding otherwise compatible capability is minor, while schema-preserving algorithm fixes, performance work, and non-identity documentation or display corrections may be patch changes. Any Package byte change still requires a new Component version and ADAQ rejects different hashes for the same Component identity and version; exact Package hashes preserve existing Runs regardless of later compatible releases. `0.x` Components are explicitly development-unstable and public developer-ecosystem releases begin at `1.0.0`. Tooling may compare SemVer compatibility when given a previous Manifest, while registry-wide enforcement remains outside M5.
