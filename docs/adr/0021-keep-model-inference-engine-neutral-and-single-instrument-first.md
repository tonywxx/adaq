# Keep model inference engine-neutral and single-instrument first

AdaQ will add an exact `adaq:model@1.0.0` inference contract, Model support in `adaq-component-sdk`, and `adaq-component new model`: a Model Component consumes frozen Feature Slots and emits a Forecast Signal Frame of one through 64 named finite numeric predictions, each with its own Prediction Kind, Forecast Value Scale, positive `horizonBars`, and required machine-readable Forecast Target, while a Strategy Component converts those signals into Target Decisions. Built-in Prediction Kinds are Score, Probability, and Expected Value; Probability requires a Binary Target, Expected Value requires a Continuous Target, and Score accepts either. A Custom Prediction Kind must declare a stable ID, version, description, and Custom Scale and receives only finite-value validation until a matching evaluator exists. M8's versioned host Catalog begins with Continuous Future Close Return and Binary Future Close Up, whose realized values the host can derive and evaluate; Future Close Up is one only when the future close is greater than the origin close and otherwise zero. Models may instead declare a Custom Forecast Target with a stable ID, version, description, and Binary or Continuous value type, but AdaQ reports no target-specific metrics without verifiable realized labels. Invalid Prediction Kind and Target value-type combinations are rejected when the Package is imported. The host derives prediction times from input Bars, and a Bar Gap makes the affected realized outcome unavailable rather than shifting the horizon. M8 supports single-Instrument models aligned with the existing Run boundary, retains Composed Strategies, and adds no Signal Component. Model Artifacts trained by Microsoft Qlib or another engine may later be exported as verified AdaQ Model Component Packages for distribution and Marketplace sale, but Qlib, Python, and training-engine-specific types do not enter the AdaQ ABI; cross-Instrument models require a later version alongside a portfolio-level Run boundary.

Forecast Value Scale is part of every Signal's compatibility contract. Probability is bounded to `[0, 1]`; Expected Value uses the native unit of its Forecast Target; Score must declare Percentile bounded to `[0, 1]`, Z-score with its exact standardization method in Dataset provenance, or a Custom Scale with stable ID, version, description, and optional finite bounds. A Custom Prediction Kind also requires a Custom Scale. Arbitrary raw Qlib or other engine scores remain importable through a Custom Scale, but AdaQ never treats them as interchangeable with Percentile, Z-score, or a different Custom Scale.

For positive finite origin and future closes, `Future Close Return@1` realizes as `futureClose / originClose - 1`, and `Future Close Up@1` realizes as one when `futureClose > originClose` and zero otherwise. A positive `horizonBars = h` selects the `h`th subsequent Closed Bar within the same Continuous Bar Segment; a Bar Gap makes the label unavailable instead of shifting the horizon. These targets use simple rather than logarithmic return and exclude fees, slippage, funding, and other execution effects, which belong to Strategy Backtest evidence. Non-positive or non-finite closes are invalid market evidence and produce no label.

The Model Component or External Model Adapter emits the final declared Scale. AdaQ validates finite values and required bounds but does not normalize an imported or generated history after the fact: full-history ranking, mean, or variance would leak future observations into earlier Signals. Scale provenance states whether normalization used a training-frozen reference distribution or a past-only rolling window and records the relevant identities and parameters; an unproven raw score uses a Custom Scale. Any future AdaQ normalization operation creates a new content-addressed derived Forecast Signal Dataset with its own causal provenance and leaves the source Dataset immutable.

Model Components reuse ordered Feature Slot semantics sourced from Market Fields, Built-in Indicators, or External Factors, but do not reuse the Strategy Component's single-Instrument per-Bar WIT records. The Model ABI is batch-first: every Prediction row carries Instrument ID and Prediction Time plus dense ordered Feature values, and every Forecast row preserves those identities with dense ordered Forecast Signal values. A Model declares its Model Scope; M8 accepts only Single-Instrument batches, while a later Cross-Sectional scope may admit several Instruments without changing Forecast Signal Dataset or Strategy boundaries. This table shape maps to Qlib's Dataset and `(datetime, instrument)` predictions without placing pandas, Python, or Qlib types in the ABI. Model-to-Model dependencies are rejected in M8. Components never call one another: during Dataset creation the host resolves the Model's acyclic Factor dependencies and supplies its canonical Prediction Batch; during Backtest it supplies finalized Forecast Signal Dataset values to the Strategy.

The host creates one Model Instance per Model Producer Segment and supplies strictly increasing Prediction Batches. An Instance may retain causal past state for sequence models, while a stateless tabular model may ignore it. Host chunk boundaries are semantically invisible: processing the same rows as one Batch or several permitted Batches must produce identical aligned Forecast rows. A Model cannot wait for future rows and then revise earlier output. Bar Gaps and Producer Segment boundaries destroy and recreate the Instance. M8 batches contain one Instrument; a future Cross-sectional scope must additionally keep all Instruments for one Prediction Time in the same Batch.

Dataset generation supplies an explicit Inference Seed when creating each Model Instance. A native Model Component has no ambient randomness, clock, network, or filesystem input and must return bit-identical finite `f64` outputs for the same Package, Feature Plan, Snapshot, parameters, Seed, and engine identity across repeated runs and permitted Batch chunkings. Conformance varies chunk boundaries and repeats the same Seed. The Seed participates in Dataset identity, so changing it creates different evidence. External Adapters such as Kronos record their sampling configuration and Seed but remain Externally Generated; a future controlled GPU or Qlib Runner may introduce an explicit tolerance-based repeatability class without weakening the native WASM contract.

M8 retains one `adaq:strategy@1.0.0` Component kind and ABI for Signal-driven, Composed, and Hybrid Strategies; these are input-graph architectures, not separate package contracts. `adaq-component new strategy <name>` generates the recommended Signal-driven template, while `adaq-component new strategy <name> --template composed` generates the existing embedded-logic pattern under the same `kind: strategy`. AdaQ derives the UI Architecture label from declared Feature sources for a Package and from the frozen Feature Plan for a Run: only Forecast Signals is Signal-driven, no Forecast Signal is Composed, and a mixture is Hybrid. The label is never stored as an author-controlled Manifest field, so it cannot disagree with the authoritative dependency graph.

Each Prediction row yields exactly one positionally aligned optional Forecast row with the same Instrument ID and Prediction Time; absence is permitted only under the declared Warmup or MissingInput rules. A Model cannot invent row identities, choose its own availability, or emit future rows. The host attaches an Available At timestamp from the controlled inference schedule. Several horizons are separate declared Signals on the originating prediction row. Generated future OHLCV or other time-series paths are a distinct future Forecast Path Artifact and do not enter M8 Signal semantics; an External Model Adapter such as Kronos derives the declared Signals from its generated path before import.

Every Forecast Signal Frame records `availableAt`, the earliest instant at which a Strategy may consume it. This is distinct from Prediction Time and is not part of the `(instrumentId, predictionTime)` row identity. Native Dataset generation derives it from the Closed Bar and deterministic inference-availability policy rather than trusting Component output; an external `.adaq-signals` row must supply it and the archive records the policy and provenance used to derive it. A Strategy receives a Signal only when `availableAt <= decisionTime`; otherwise the input remains unavailable and produces `Run Pause::MissingInput`. File creation or import time never substitutes for signal availability.

M8's native `closed-bar@1` availability policy sets Prediction Time and `availableAt` to the input Closed Bar's close boundary. The host evaluates the Strategy after that boundary, and the Execution Profile cannot fill the resulting intention before the next Bar. M8 does not invent a wall-clock inference delay for offline batch generation. A future controlled Runner may record observed or configured latency as a later `availableAt`; an external Dataset may also declare a later value but is invalid if availability precedes the information cutoff required by its declared prediction inputs.

Each Model declares exact `warmupBars` measured in complete upstream-ready Feature Frames. Dataset-generation Warmup composes upstream Feature Warmup with Model Warmup; a finalized Dataset preserves unavailable rows and their reasons. A modular Strategy is not invoked before every required Forecast Signal is available, and a missing post-Warmup Dataset row produces `Run Pause::MissingInput` rather than zero. A Bar Gap rebuilds the stateful Factor, Model, or Strategy instances active in the current phase and restarts their Warmup, so analytical context never crosses missing market evidence.

M8 replaces Indicator Plan with an immutable Feature Plan contract used separately by Model inference and Strategy Backtest. Dataset creation freezes the exact `Market/Indicator/Factor -> Model` graph, ordered Slot bindings, parameters, Warmup, Snapshot, and engine, Catalog, schema, and Package identities before producing a Forecast Signal Dataset. A modular Backtest freezes `Forecast Signal Dataset -> Strategy`, plus any other Strategy Features, and never invokes the producing Model implicitly; the Dataset already binds its exact Model Artifact or Package and inference provenance. A Composed Strategy continues to freeze and execute its direct Market, Indicator, and Factor graph without a Dataset. New executions bind their Feature Plan directly; AdaQ's pre-v1 compatibility policy requires no legacy Indicator Plan reader, migration, or dual-schema path.

Dataset-first is mandatory for M8's modular research path: users create or import an immutable Forecast Signal Dataset in Models, may evaluate that same evidence independently, and then select it in Backtest. This prevents hidden inference inside a Backtest and lets several Strategies reuse identical predictions. A future controlled online Runner may stream the same Forecast Signal contract in memory for latency without changing Model, Signal, or Strategy semantics.

Dataset creation uses a separate Dataset Generation Attempt with `Pending`, `Running`, `Completed`, `Failed`, and `Cancelled` lifecycle states. Only a fully generated, validated, content-hashed result is atomically published as an immutable Forecast Signal Dataset; partial rows cannot enter Evaluation or Backtest. Failed and Cancelled Attempts retain their exact configuration, Package, Snapshot, Seed, progress, diagnostics, and error evidence. Retry creates a new Attempt and may deduplicate an already finalized identical Dataset. The UI paints progress before native work, exposes accessible busy state and cancellation, and suppresses duplicate starts. M8 does not pretend to checkpoint an opaque stateful WASM resource: retry after interruption replays from the Producer Segment boundary. A future controlled Runner may add safe Attempt checkpoints without changing the Dataset format.

A Strategy Package never pins a Forecast Signal Slot to a Model ID, Model Artifact, or Dataset. It declares a semantic requirement comprising Prediction Kind, Forecast Target, `horizonBars`, and the Signal value contract. Backtest configuration binds a compatible Dataset Signal, and the frozen Feature Plan records its exact Dataset ID, Signal name, Model Artifact or Package provenance, and contract identity. This lets one Strategy consume compatible Qlib, Kronos Adapter, or native AdaQ predictions without recompilation while preserving exact Run evidence.

A Forecast Signal Dataset manifest contains one or more ordered Model Producer Segments rather than assuming one Artifact forever. Each Segment assigns a non-overlapping Prediction Time range to one exact Model Artifact and its inference configuration and provenance; ranges may not overlap or leave a Present Signal row without one producer. Every Segment in one Dataset must emit the same Signal names and contracts. M8's normal static-model Dataset has one Segment, while a future Qlib walk-forward export may identify each retrained Artifact without changing the archive or Parquet identity model. Artifact hashes remain in the manifest instead of being repeated per row. Evaluation Evidence State is computed per Segment against its own training, fitting, and normalization windows, and the Report summary uses the most conservative resulting state.

A modular Backtest accepts a Forecast Signal Dataset only when its exact Market Data Snapshot identity, Instrument, Venue, and Bar Interval match the Backtest inputs. The selected Backtest window may be a subset of the Dataset's coverage, and several selected Signal Datasets must bind the same Snapshot. M8 performs no implicit resampling, forward filling, or approximate time join; an aligned missing Signal produces `Run Pause::MissingInput`. This prevents predictions derived from one market-data history from being silently executed against another.

M8 also accepts immutable Forecast Signal Datasets from local External Model Adapters so users can evaluate pretrained or externally trained models without running arbitrary Python inside the desktop application. The reference path uses `Kronos-small` with `Kronos-Tokenizer-base`, converts its forecast K-line path into declared Forecast Signals, and binds the result to the exact Model Artifact, Market Data Snapshot, prediction configuration, and inference trust state. M8 delivery includes a complete user guide covering external-model setup, artifact acquisition, adapter execution, canonical Dataset generation and import, Strategy consumption, Backtest and Validation, provenance inspection, and troubleshooting through this Kronos example. Imported Signal Datasets are marked Externally Generated and remain usable local research evidence, but AdaQ does not claim that their inference was reproduced or free of lookahead; only conformance-verified AdaQ Model Components or future controlled Runners may produce Verified inference, and only verified AdaQ Model Component Packages are eligible for future Marketplace distribution.

M8 keeps the existing self-contained `.adaq` archive shape and 64 MiB limit: a native Model Component compiles its inference logic and small weights into `component.wasm` beside `manifest.json`. M8 adds no weight-asset loader, ambient filesystem capability, or second native model runtime. Large PyTorch models such as Kronos remain External Model Adapter inputs; a later controlled Qlib or ONNX integration may replace this pre-v1 package decision with hashed weight assets.

Every Model Artifact has a content-derived identity and Model Provenance covering its exact source revision, weight hashes, Tokenizer, Normalizer and Feature Processor hashes, architecture/config identity, framework and version, Adapter/exporter version, upstream source and licence, and known training data and method. Unknown upstream facts remain explicitly `unknown` rather than inferred. Incomplete external provenance may support warned local research, but missing source, licence, or weight identity prevents Marketplace-ready status; future Marketplace review separately verifies redistribution rights and author claims.

M8 adds no separate Model Artifact Library or third import format. Importing a native Model Component Package registers its embedded Artifact identity and Provenance; importing a `.adaq-signals` archive registers the referenced external Artifact metadata without copying large external weights. Component, Signal Dataset, and Forecast Evaluation views link the same Artifact record. A later Qlib training workspace may add experiment and checkpoint management when AdaQ itself produces multiple Artifacts.

Forecast Signal Dataset metadata, identity, Model Producer Segments, references, availability policy, and trust state live in SQLite, while the authoritative aligned Signal rows live in immutable, content-hashed Parquet sorted by Instrument ID and Prediction Time. Every row carries `availableAt`; Present rows require every declared finite Signal, Warmup or MissingInput rows retain their status and null outputs, and duplicate row identities are invalid. Every Present row resolves to exactly one Producer Segment without repeating Artifact hashes in Parquet. The Dataset ID hashes finalized canonical metadata together with the Parquet content hash, and referenced Datasets cannot be deleted. DuckDB may later provide a rebuildable query and analytics layer directly over these Parquet files; it does not replace their authoritative evidence role.

Portable Signal evidence uses one `.adaq-signals` ZIP archive containing exactly a canonical `manifest.json` and `signals.parquet`. Import validates bounded archive structure, schema, hashes, column types, sorted unique row identities, Snapshot and Instrument alignment, then publishes the Parquet atomically. The extension identifies the artifact type only; Model producer, Adapter, and inference trust state remain authoritative Manifest fields, so native, external, and future controlled Runner outputs do not require different file formats.

M8 persists a separate immutable Forecast Evaluation Report for prediction quality, bound to the exact Model Producer Segments and their Artifacts or Packages, Forecast Signal Dataset, Market Data Snapshot, Forecast Targets, Prediction Kinds, inference trust state, and evaluation configuration. It does not reuse or replace the downstream Validation Report, which continues to evaluate Strategy decisions and Backtest evidence. Custom Targets or Prediction Kinds without a matching evaluator retain coverage, distribution, and provenance evidence without invented specialized metrics.

Every Forecast Evaluation Report records an Evaluation Evidence State. It is Out-of-sample only when complete provenance shows that its evaluation window does not overlap any training, fitting, or normalization-reference window; it is Overlapping when a known overlap exists and Unknown when those upstream windows are incomplete. All three remain usable for local research, but Overlapping and Unknown reports display an explicit warning and cannot be represented as out-of-sample, Verified, or Marketplace-ready merely because their metrics are strong. Qlib train, validation, and test segments map into this provenance; an external pretrained model such as Kronos remains Unknown when its complete training boundary cannot be established. Backtest Runs retain the same evidence state without blocking execution.

The first Forecast Evaluation Report records common coverage, missingness, distribution, and time-window stability; Score outputs add time-series Pearson IC, Spearman Rank IC, window IC/ICIR, and five-quantile realized Targets; Probability outputs add Brier Score, Log Loss, ROC AUC, and calibration; Expected Value outputs add MAE, RMSE, mean bias, and Pearson correlation. It does not relabel single-Instrument statistics as cross-sectional IC or treat Strategy profitability and portfolio turnover as Model metrics.

Every Forecast Evaluation, Backtest, and Validation metric shown in the desktop UI has an adjacent accessible information control that works by pointer hover, keyboard focus, and click. One canonical metric definition supplies its plain-language meaning, formula, direction of interpretation, mathematical range when one exists, contextual caveat, and a link to detailed reference documentation; the UI must not invent universal investment-quality thresholds for context-dependent statistics.

Research navigation adds a Models entry between Components and Backtest. Its single page uses three top-level Tabs: Create Dataset runs a native Model or imports `.adaq-signals`; Signal Datasets lists and inspects immutable Signals, trust, and Provenance; Evaluation Reports creates and inspects Forecast Evaluation Reports. These Tabs participate in the existing Back/Forward and tab-restoration behavior and remain keyboard accessible and usable in narrow desktop windows.

M8 ends at the offline research loop: Feature and Factor inputs, Model inference, immutable Forecast Signal Datasets, Forecast Evaluation, and Strategy Backtest integration. It does not add training or tuning workspaces, an embedded Microsoft Qlib or Python runtime, Cross-sectional Models, live Signal feeds, an online Strategy Engine, Portfolio Optimization, OMS/EMS or venue submission, Marketplace publishing, or a GPU/ONNX controlled Runner. The Artifact, Provenance, Producer Segment, Dataset, Signal, and Component boundaries are deliberately shaped so those later milestones can add execution environments without redefining M8 research evidence.
