# Keep the execution contract in backtest-core and orchestration in the application

The Target Decision and simulation contract types (Target Decision, Execution Profile, Simulated Order, Fill, SimulationResult) belong to `adaq-backtest-core`; the application `run_engine.rs` depends on that crate and emits its Target Decision type directly, so no field-by-field mapping layer exists between Run execution and simulation. `run_engine.rs` remains in the application crate as the orchestrator of Market, Built-in, Factor, and Strategy evaluation, because it serves two consumers (the Backtest Run pipeline and Dataset Generation feature materialization) and stays Tauri-independent without needing a crate of its own. `SnapshotStore` remains in `adaq-backtest-core`: moving it into `adaq-data-core` would force arrow and parquet dependencies onto a lightweight market-data crate without concentrating any complexity, and a dedicated snapshot crate would be a hypothetical seam. This clarifies the tension with ADR-0020's phrasing that `adaq-backtest-core` "does not absorb full-simulation work early": full simulation has since landed in the crate by accretion, and this record is the authoritative split going forward — the crate owns execution and simulation contracts, the application owns orchestration and persistence, and no mapping types duplicate across the seam.
