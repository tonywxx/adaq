# Promote the m8 module into named Forecast Signal Dataset and Forecast Evaluation modules

The flat `m8.rs` module (3381 lines) carried two responsibility areas with disjoint consumers — Forecast Signal Dataset management (consumed by `dataset_generation/runner.rs` via its types and helpers) and Forecast Evaluation (referenced only by `lib.rs` command registration), plus shared helpers — so we split it into two directory modules named after the canonical CONTEXT.md domain terms: `forecast_signal_dataset/` (dataset management, `close_time`, `write_rows`, `hash`) and `forecast_evaluation/` (report generation, metric catalog, evidence state). `BacktestSignalDataset` stays in `forecast_signal_dataset` because it is a reader of signal-dataset Parquet and its consumers (`backtest/`, `component_library/tests.rs`, `local_research.rs`) are unchanged; moving it into `backtest/` would be domain-purity churn risking a dependency cycle. The two modules may reference each other across the crate-internal boundary (dataset-side archive validation uses `score_scale_provenance`; evaluation reads dataset rows and hashes), which is legal within a crate and adds no coupling direction beyond what already existed inside `m8.rs`. Tauri command names (`signal_dataset_*`, `forecast_evaluation_*`) and SQLite table names are unchanged; only the Rust module names change. Milestone naming (the `m8_model_fixture.wasm` fixture, `docs/m8-manual-acceptance*`, the frontend acceptance-doc test, and README milestone rows) is out of scope: those are M8-milestone references, not module references.
