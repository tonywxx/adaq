# Centralize Feature semantics in a host engine

AdaQ V1 adds one Tauri-independent `adaq-feature-engine` that extends the existing Feature Plan and materialization path for historical research, Factor evaluation, Model training and inference, Backtest, and Paper Trading. It orchestrates Canonical Market Data, the existing specialized `adaq-indicator-engine`, declared causal transformations, compatible Factor outputs, exact Warmup and availability, Point-in-Time Instrument Universes, and immutable Fitted Transformation Artifacts, producing Feature Datasets for batch work and equivalent Feature observations for online work. Historical and online execution share Definition and Plan semantics so training-serving skew is visible rather than accidental. AdaQ does not add an `adaq:feature` Component ABI or a parallel `adaq-feature-process`; custom deployable analytical logic remains a Factor Component, while the host owns Feature resolution and evidence.
