# Keep one Factor product with two execution scopes

AdaQ V1 keeps one user-facing Factor Component kind, one `factor-*.adaq` package and import workflow, and one Component Library category, but requires every Factor Manifest to declare exactly one `factorScope`: `time-series` or `cross-sectional`. Factor ABI v2 exposes distinct Time-Series and Cross-Sectional worlds rather than adding a cosmetic label to the existing single-Instrument `ClosedBar` contract. A Time-Series Factor Instance processes one Instrument in causal Observation Time order with Instrument-isolated state and Warmup; a Cross-Sectional Factor evaluation receives one deterministic Instrument-keyed batch bound to an exact Point-in-Time Instrument Universe and returns outputs keyed to those Instruments. Packages export only the world matching their declared Scope, and the host rejects Manifest, world, input-cardinality, ordering, membership, availability, or output-identity mismatches before evidence is published. Economic descriptions such as momentum, value, quality, volatility, liquidity, and size remain optional Factor Tags with no runtime meaning. The pre-V1 Factor ABI may be replaced under ADR 0022 because preserving a single-Instrument contract would make Cross-Sectional support nominal rather than executable.
