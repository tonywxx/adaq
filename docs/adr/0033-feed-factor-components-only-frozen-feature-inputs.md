# Feed Factor Components only frozen Feature inputs

AdaQ V1 removes the Factor ABI v1 assumption that a Component receives provider-shaped `ClosedBar` values and instead requires every Factor Manifest to declare ordered Feature Slots. Before research materialization, Backtest, Model Dataset generation, or Paper Trading, the host validates an acyclic dependency graph, freezes the exact Feature Plan, and uses `adaq-feature-engine` to resolve Canonical Market fields, Built-in Indicators, declared causal transformations, Fitted Transformation Artifacts, and compatible upstream Factor outputs. Factor ABI v2 receives only identity-preserving Factor Input Batches matching those Slots: Time-Series batches contain one Instrument in causal Observation Time order, while Cross-Sectional batches contain one Observation Time and its exact Point-in-Time Instrument Universe. Missingness and availability remain explicit, and a Component cannot fetch data, read files, inspect ambient time, refit transformations, or silently substitute an input. Historical and online paths execute the same Feature definitions and Factor contract; finalized outputs publish an immutable Factor Dataset rather than mutating their Feature Dataset. This centralizes data and preprocessing evidence in the host while leaving custom analytical factor logic deployable as a sandboxed Component.
