# Gate Factor Component generation with promotion and equivalence

AdaQ V1 supports automatic `factor-<name>-<semver>.adaq` generation and atomic Component Library import through two evidence-preserving paths. A Declarative Factor Definition is evaluated directly in Factor Lab, promoted through an Approved Factor Promotion Decision, rendered into a versioned Rust SDK project, and built in a background Component Build Attempt. A Custom Factor Project is first built as a non-imported candidate, executed in the same WASM sandbox to produce its Factor Dataset and Evaluation Reports, and becomes import-eligible only after an Approved Promotion Decision. Both paths pin source, generator or template, SDK, ABI, compiler, target, commands, runtime, and candidate hashes; validate Package, Manifest, capabilities, ABI, finite outputs, determinism, and resource limits; and produce a Component Equivalence Report by replaying exact frozen inputs and comparing identities, availability, missingness, contracts, and required numeric results with the approved research evidence. Only a fully passing Attempt is atomically imported, initially as version `0.1.0`; failed or cancelled Attempts retain diagnostics and never publish partial packages. ADAQ does not pretend to translate arbitrary Python or notebook code into Rust, execute builds on the UI thread, copy performance claims into Component Meta, or bypass normal import validation for generated Packages.
