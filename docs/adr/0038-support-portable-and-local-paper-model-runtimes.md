# Support portable and Local Qlib Paper Model runtimes

ADAQ V1 keeps one Model product and one Prediction Batch to Forecast Batch contract while permitting three Model Deployment Profiles: self-contained WASI Model, content-addressed ONNX Model, and device-bound Local Qlib Paper. Factor and Strategy Components remain WASI-only. WASI and ONNX candidates must pass their supported Model Exporter, package validation, runtime limits, and Component Equivalence before Paper Trading. A Qlib Artifact that cannot be exported, or whose export is not equivalent to the original, may instead qualify its exact original Artifact and frozen Python/Qlib environment for Local Qlib Paper; `adaq-model-runner` executes it as a supervised child-process sidecar that receives only frozen Prediction Batches and returns Forecast Batches, while the host Bot Supervisor retains credentials, orders, positions, risk, and fail-safe control. The runner has no order authority, and an invalid, late, crashed, or unavailable inference pauses new risk. An original runtime that cannot pass schema, finite-value, deadline, and declared exact or tolerance-based replay checks remains Research Only. Local Qlib Paper is excluded from Marketplace, remote deployment, and Real Trading in V1. This replaces M8's two-file, WASM-only Model Package restriction for V1 Models without changing the established Factor or Strategy package boundary.
