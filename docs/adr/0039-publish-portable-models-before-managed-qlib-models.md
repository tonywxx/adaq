# Publish portable Models before managed Qlib Models

The post-V1 ADAQ Marketplace will first accept only qualified WASI and ONNX Marketplace Model Candidates, while a later release may accept a separately qualified Managed Qlib runtime bundle for models that cannot become portable. Raw Python projects, notebook environments, Local Qlib Paper status, and strong research metrics never confer Marketplace eligibility. Every Candidate must bind exact Model Provenance, publisher and redistribution rights, signed runtime payload identities, platform and resource limits, security evidence, and Model Runtime Qualification; exported Models also require Component Equivalence. Large graphs and weights live as entitlement-protected, content-addressed Marketplace artifacts referenced by a signed Model Package rather than being forced into the current small archive. A Managed Qlib Product must execute in a restricted ADAQ runner that has no credentials or order authority and communicates only through the Model prediction contract. Marketplace acceptance remains separate from Real Trading Qualification. This sequencing gives portable Models the smallest auditable supply-chain surface while preserving a later path for valuable non-exportable Qlib Artifacts.
