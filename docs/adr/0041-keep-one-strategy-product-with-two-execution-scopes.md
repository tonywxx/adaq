# Keep one Strategy product with two execution Scopes

ADAQ V1 keeps one `strategy` Component kind, Package, SDK, import, and lifecycle while requiring every Strategy to declare Single-Instrument or Portfolio Scope and execute through the corresponding ABI world. Single Instrument preserves the existing per-Instrument Target Decision contract. Portfolio receives one deterministic, identity-preserving input for an exact decision time, Point-in-Time Instrument Universe, Feature Plan, Forecast Signals, availability, missingness, and current Portfolio State, then returns a complete Instrument-keyed Portfolio Target and cash reserve. It never returns orders or receives broker authority; the Rust host validates the complete target and retains risk and execution ownership. Independently running one Single-Instrument Strategy per Instrument is not treated as an equivalent portfolio because those Instances cannot safely coordinate shared capital, Top-N selection, turnover, cash, or portfolio-wide limits. One product kind avoids duplicating package infrastructure while separate ABI worlds preserve the materially different cardinality contracts.
