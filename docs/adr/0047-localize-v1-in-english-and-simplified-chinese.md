# Localize V1 in English and Simplified Chinese

ADAQ V1 ships exactly two bundled GUI translation-resource locales: English (United States) `en-US` and Simplified Chinese `zh-CN`. Settings > General exposes the device-local choices System, English (US), and 简体中文; System resolves a Chinese system language to `zh-CN` and every other language to `en-US`, while an explicit choice remains fixed. The selected Interface Locale is loaded before the first application paint, changes immediately without restart, survives sign-out and research-data reset, and is not synchronized to the User Profile. The GUI uses the direct `i18next` dependency with `react-i18next`, updates the document language, uses native `Intl` formatting, bundles all resources with the application, and falls back to `en-US` for a missing key. Translation changes presentation only: canonical identifiers, wire values, exact financial values, Venue-time identities, hashes, evidence, exports, provider payloads, technical diagnostics, and user-authored names remain unchanged; translated summaries may appear beside preserved raw details. CI must verify locale-key and interpolation-variable parity, while route-level acceptance covers both locales, persistence, first-paint behavior, accessibility labels, and layout overflow. Runtime machine translation, downloaded language packs, server-synchronized language preferences, and additional locales are outside V1.
