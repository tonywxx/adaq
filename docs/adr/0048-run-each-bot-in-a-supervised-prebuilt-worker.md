# Run each Bot in a supervised prebuilt Worker

ADAQ V1 implements Trading Bot execution as a host-owned Bot Supervisor plus one isolated Bot Worker child process per active Bot. The Worker is an instance of one prebuilt, versioned, signed, and application-bundled Rust `adaq-bot-worker` Sidecar; Sidecar describes packaging while child process describes runtime isolation. A Worker verifies one immutable qualified Bot Deployment Bundle, evaluates only its frozen Feature, Model, and Strategy pipeline, and returns Strategy Targets and diagnostics. It never receives credentials, owns capital, applies final hard Risk, manages orders, or calls a Paper Provider. The Bot Supervisor remains the sole authority for market-data distribution, account reconciliation, capital reservations, Risk Decisions, OMS, Paper Execution Adapters, durable event journals, Live Control Leases, emergency controls, Worker deadlines, and recovery. A Worker crash, invalid output, missed heartbeat, parent loss, or runtime-limit breach blocks new risk and produces retained evidence; restart requires bundle verification, state replay, and account reconciliation before resuming. Local Qlib Paper remains a separately supervised `adaq-model-runner` with the same no-credential and no-order boundary. Strategy source generation and compilation occur only when a research candidate is promoted into a qualified Component, never during Bot deployment or startup. V1 accepts per-Bot process overhead for fault isolation; a measured post-V1 need for hundreds of concurrent Bots may justify a qualified Worker pool without changing order authority.
