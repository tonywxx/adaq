# Protect Paper credentials in the host and operating-system secret store

ADAQ V1 stores Alpaca Paper and OKX Demo credential values only in the operating-system secret store under a User- and device-scoped random Secret Reference; SQLite retains the separate Paper Connection Profile, masked display suffix, provider, fixed Paper or Demo environment, allowlisted endpoints, capability evidence, timestamps, and health, but never an API secret or passphrase. Alpaca Paper uses its Paper API Key ID and Secret Key against the fixed Paper trading endpoint and Alpaca Market Data endpoint; OKX Demo uses its Demo API Key, Secret Key, and Passphrase while the Adapter always enforces simulated-trading mode and rejects withdrawal capability. The Host Connection Manager and Paper Execution Adapter are the only credential consumers: the GUI, Bot Worker, Local Qlib runner, Python process, WASM Component, Deployment Bundle, exports, diagnostics, and logs receive no credential value. Saving or rotating a Profile performs a read-only Paper Connection Test that verifies authentication, provider environment, account identity, Valuation Currency, permissions, clock, and capabilities without placing or cancelling an order; environment, endpoint, account, or permission mismatch fails closed. V1 rejects Live endpoints and credentials, does not permit arbitrary base URLs, and never treats a masked secret or encrypted SQLite column as a Secret Reference. Rotation creates and validates a replacement secret before retiring the prior one; deletion is blocked while an active Bot depends on the Profile, then invalidates the Profile and requires reconciliation before another start. Sign-out and research-data reset do not expose or silently transfer credentials to another User, and credential deletion remains an explicit Connections operation.
