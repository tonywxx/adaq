# Make Feature scope and availability explicit

ADAQ M10 assigns every Feature Definition exactly one Pointwise, Time-Series, or Cross-Sectional Feature Scope and evaluates it only against the matching observation boundary. A derived Feature's Available At is the latest availability among its inputs and Fitted Transformation Artifact; corporate-action and other external facts use recorded provider publication evidence rather than effective dates, causal Features use only forward adjustment, and local computation time does not alter historical identity. An unavailable input preserves its row and typed reason, affects only dependent graph branches, and restarts Warmup for dependent stateful nodes without interrupting independent branches; expected undefined arithmetic is Unavailable, while non-finite engine output or a broken invariant fails the Attempt. Cross-Sectional operations preserve the exact Universe and freeze minimum count, coverage, tie, and percentile rules. Fitted transformations publish one immutable Artifact per node through exact, fold-specific Fitting Protocols and Attempts, while materialization may only apply them. These explicit contracts cost separate execution paths but prevent hidden cross-Instrument dependencies, lookahead, imputation, and chunk-dependent evidence.

Every M10 Feature value is a finite `f64` or typed Unavailable; calendar, session, Boolean, and categorical semantics use explicit versioned numeric encodings instead of a second runtime type system. One Definition publishes one through 64 ordered named outputs, while V1 Cross-Sectional execution binds one Venue, Asset Class, Bar Interval, Price Basis, and Valuation Currency. Pointwise and Time-Series branches stream by Instrument and Continuous Bar Segment, Cross-Sectional branches process one complete Observation-Time batch, and execution chunk size never changes Feature evidence identity or values.

A M10 dependency graph may expand only from Pointwise to Time Series to Cross Sectional, and Cross-Sectional outputs are terminal until a demonstrated need justifies a more complex scheduler. Observed and Reconstructed Universes may produce Feature evidence with their exact Evidence State, while Unknown makes the complete Cross-Sectional batch Unavailable. Fitted nodes explicitly choose Pooled-Universe or Per-Instrument parameters; instantaneous Cross-Sectional normalization is not a fitted Artifact. Preview may bound Observation Times but never sample away members of a Cross-Sectional batch or fit new parameters.

Return operators are backward-looking only; future outcomes remain Forecast Targets rather than consumable Features. Canonical Decimal inputs remain authoritative while the Feature Engine performs a checked deterministic conversion to finite analytical `f64` without claiming decimal bit-exactness. Division by zero, non-positive logarithms, and operator-detected overflow are typed Unavailable, while an Indicator or Feature Engine that actually emits a non-finite result fails the Attempt.

Rolling operators require a full count of consecutive eligible Closed Bars, reset the affected branch at a Bar Gap or unavailable dependency, and never count Scheduled Closures as missing observations. Realized Volatility is the per-Bar population standard deviation of backward log returns; annualization is explicit and calendar-bound. Liquidity exposes Quote Volume, rolling Quote Volume, zero-volume state, and unit-preserving Amihud Illiquidity rather than an unsupported Turnover Ratio. Session Progress counts only eligible Venue-local trading minutes, while Split and Dividend transformations move forward from available and effective evidence without rewriting historical values.

Cross-Sectional Rank uses ascending average ties; Percentile is `(rank - 1) / (n - 1)` with `n = 1` Unavailable, and reverse order is an explicit parameter. Cross-Sectional Z-score uses population variance and makes zero variance Unavailable. Fitting Protocols require an explicit minimum sample count and frozen quantile parameters; nearest-rank Winsorization or Standardization with insufficient samples fails without publishing an Artifact. An Artifact's deterministic Eligible At comes from fitting inputs, while local Created At remains operational audit metadata and does not change historical Feature identity.
