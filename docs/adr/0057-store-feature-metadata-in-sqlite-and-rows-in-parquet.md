# Store Feature metadata in SQLite and rows in Parquet

ADAQ M10 stores User-scoped Feature Definitions, Plans, Fitted Transformation Protocols and Artifacts, Materialization Attempts, manifests, references, and lifecycle state in SQLite while storing immutable content-addressed Feature Dataset rows in Parquet. Dataset identity binds the exact User, Snapshot, Point-in-Time Instrument Universe, Plan hash, Artifact identities, engine identities, parameters, and Seed; matching Pending or Running requests coalesce, a matching Completed Dataset is reused, and Retry creates a new Attempt that retains its source evidence. Fitting uses the same coalescing, reuse, Retry, and retained-evidence rules for exact Protocol identity. Parquet uses one wide row per Instrument ID and Observation Time, with each output retaining its finite `f64` value, Available At, state, and versioned Unavailability Reason through a canonical Manifest mapping. Materialization writes only to private staging, validates complete schema, rows, and hashes, atomically publishes the payload, and only then records Completed; cancellation or startup recovery never exposes partial evidence. A referenced Dataset or Artifact is deletion-locked, and shared payload bytes are removed only after the last User reference disappears. This split reuses the existing local research boundaries and gives columnar consumers efficient immutable evidence without putting large analytical matrices into SQLite or inventing an export format.

Each Dataset exposes a rebuildable Summary of per-output coverage, Unavailability Reason counts, minimum, maximum, mean, and population standard deviation plus bounded filtered row pagination. The Summary is content inspection rather than research evaluation and never becomes a Factor, Model, or profitability claim.

The device runs one heavy Feature Fitting or Materialization Attempt at a time through a persistent FIFO queue. Pending Attempts survive restart, a stale Running Attempt becomes Failed with typed interruption evidence, and Retry creates a new identity; progress advances only after complete Feature Observations are committed and never presents an invented remaining-time estimate.

Definition, Attempt, Artifact, Dataset, and mutable presentation records remain User-scoped. Exact payload bytes may be deduplicated on one device, but deduplication never grants visibility or reuse rights to another User; mutable names, descriptions, and tags stay outside semantic hashes.
