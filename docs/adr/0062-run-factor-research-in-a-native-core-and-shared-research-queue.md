# Run Factor research in a native core and shared research queue

ADAQ M11 adds one Tauri-independent `adaq-factor-research` crate that owns Factor materialization, the Factor Metric Catalog, evaluation, Research Families, Promotion Policies, Reports, and Decisions while `adaq-feature-engine` remains the source of frozen Feature semantics and Component tooling owns ABI and package validation. M11 uses only the ADAQ Native Research Engine; Qlib and Python execution remain M12 work, and results from future engines retain separate Research Engine Provenance unless explicit equivalence says otherwise. The application runs Feature and Factor heavy work through one persistent device-wide research FIFO, while Tauri commands only validate, enqueue, cancel, retry, and query User-scoped Attempts, trading parallel throughput for bounded memory, responsive UI scheduling, restart recovery, and a scheduler M12 can extend without another competing worker pool.
