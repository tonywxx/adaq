# Separate editable Python research from portable Components

ADAQ V1 adds one versioned Python Research SDK and locally editable Python Research Projects for offline Factor, Model, and Strategy experimentation over frozen host-supplied inputs, while retaining Component Packages as the portable deployment boundary. Each Project declares exactly one Factor, Model, or Strategy kind and one stable Python entry point; it may contain multiple modules and outputs, but a notebook or mixed-domain pipeline is not the authoritative execution or publication source. Factor and Strategy Projects explicitly choose Imperative Python or Portable Definition: the former executes arbitrary source for Research Only, while the latter uses Python only to construct canonical Host contracts from the existing Feature Operator Catalog or finite Declarative Strategy Operation Catalog. Model portability remains the responsibility of registered Model Exporters. M14 feeds only a canonical Declarative Definition or supported Model Artifact into a fixed Rust SDK Generator; Python source, Runtime, wheels, environments, and Dependency Locks do not enter the generated `.adaq` package. Python receives no credentials, order API, or deployment authority: only an exact qualified Local Qlib Model may enter supervised Paper inference, while deployed Factors and Strategies remain WASI Components. Every generated or exported candidate must pass conformance and Component Equivalence; ADAQ never infers portability or promises automatic translation of arbitrary Python or notebooks. Distributing WASM or ONNX omits source and raises reverse-engineering cost but does not guarantee secrecy on a User-owned device; stronger protection requires managed remote execution. V1 may import and export source-visible Python Research Projects locally, while hosted Marketplace, payments, licence enforcement, and managed execution remain post-V1.
