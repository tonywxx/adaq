# Treat local Python research as explicitly trusted code

ADAQ V1 executes only User-created or explicitly trusted Python Research Projects in cancellable child processes and never runs a Project merely because it was imported or bundled with the application. A Python Project Trust Decision binds one exact Project Revision hash; the guided tutorial may show three Revisions in one confirmation but records three independent Decisions. Installation, Marketplace review, name continuity, and trust in an earlier Revision confer no authority, and changing source, entry point, or Dependency Lock requires another explicit Decision only for that changed Project. The Host supplies frozen read-only inputs through typed SDK contracts, validates returned outputs, and alone publishes authoritative evidence; it exposes no SQLite path, internal Parquet layout, credential, provider token, signing key, order endpoint, secret, or deployment authority. Each Runner receives a private working directory and an allowlisted child environment, while capped stdout and stderr logs remain User-scoped and are never uploaded or shared automatically. Process isolation and reduced ambient authority contain lifecycle failures but are not presented as a cross-platform filesystem or network security sandbox for arbitrary Python, so V1 does not promise to prevent trusted code from accessing ambient User files or networks. Running unfamiliar community code under enforced filesystem, network, dependency, and capability isolation requires a separately reviewed post-V1 Marketplace sandbox.
