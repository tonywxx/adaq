# Freeze Python source, environments, and Trials before research

ADAQ treats each Python Research Project as a User-scoped mutable Working Copy under ADAQ local data but freezes an immutable, content-addressed Python Project Revision before every execution. Its fixed layout is `adaq-project.toml`, `pyproject.toml`, ADAQ-generated `pylock.toml`, `src/project.py` plus optional declared modules, `README.md`, and `LICENSE`; an immutable lower-kebab-case Project ID begins with the matching `py-factor-`, `py-model-`, or `py-strategy-` prefix. Importing an external directory copies it without implicit synchronization, edits only move its independently visible state among Clean, Dirty, and Invalid, and a running Attempt never hot-reloads or automatically executes later edits. The exact-schema Manifest supplies only semantic execution identity: Project ID, Kind, Mode when applicable, Scope, stable entry point, SDK and Runtime Profiles, typed parameters, ordered inputs and outputs, Target or Signal contracts, Dependency Lock hash, and resource requests bounded by a versioned Host policy. Unknown fields, enum values, and unsupported schema versions cannot Prepare or Run and are never silently upgraded, though their source and historical evidence remain inspectable and exportable. Name, description, tags, README, and licence remain presentation or distribution metadata. The Revision binds that Manifest and declared source and resolves the Runtime Profile to an exact platform-specific Runtime artifact, while the Python Research Attempt also binds frozen input evidence, one normalized parameter set, Seed, applied resource policy, outputs, diagnostics, and logs.

`pyproject.toml` expresses editable dependency intent, while explicit Sync Environment resolves trusted-index, wheel-only dependencies and atomically replaces `pylock.toml`; Run never resolves, edits, or installs dependencies. ADAQ prepares and reuses isolated environments by exact runtime and Lock identity through a separate operation that does not grant execution trust. Cross-process tables use identity-preserving Arrow-compatible schemas with Host-authorized Parquet or Arrow IPC transport; pandas is an SDK convenience rather than an authoritative index, order, or dtype contract. Projects declare typed parameters, but ADAQ owns parameter-search expansion and records each parameter set as its own Trial instead of accepting a hidden multi-Trial script result. V1 opens the Working Copy in the User's existing editor and supplies Validate, Sync or Prepare Environment, Run, Cancel, Open Folder, Export, logs, and result navigation rather than embedding an IDE, notebook server, or terminal. Validate is static and needs no Python, Prepare does not ask for execution trust, and Run freezes the Revision and requests trust only when required.
