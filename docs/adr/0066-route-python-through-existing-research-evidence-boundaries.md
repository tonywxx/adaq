# Route Python through existing research evidence boundaries

ADAQ adds Python as an authoring and execution source inside the existing Factor, Model, and Strategy evidence domains rather than creating parallel Python Labs. A Python Factor Candidate is a third, explicitly versioned Candidate source that binds an exact Python Project Revision and environment, materializes the standard Factor Dataset, and reuses M11 Evaluation, Research Family, and Promotion; arbitrary Python may become Research Validated after repeatability and existing evidence gates pass but must be re-expressed through a supported portable definition before Component eligibility. Introducing that source advances the exact Factor Research Schema from `1.0.0` to `1.1.0`; incompatible stored evidence is rejected until the User explicitly performs a device-level Factor Research Reset, with no migration or automatic deletion. A Python Model Project runs against Host-frozen Train and Validation partitions while Test labels remain Host-only, then returns typed Model Artifacts and Forecast Signals; Qlib is the first supported Adapter, other locked frameworks remain Research Only by default, and deployment still requires a supported Exporter or qualified Local Qlib Paper Profile. A Python Strategy Project receives the same scope-correct Decision Batch and Portfolio State semantics as a Strategy Component and returns only Target Decisions or Portfolio Targets into Host-owned Risk, Execution, and research simulation; Qlib-native portfolio actions remain separately labelled Research Backtest evidence and never become ADAQ orders or Backtests.
