# Install and manage Python Runtimes on demand

ADAQ does not rely on a system Python or require the User to install or select an interpreter. The application carries a versioned runtime manager and, only after the User starts Python setup, downloads and verifies an exact platform-specific ADAQ Python Runtime. A Project declares a logical Runtime Profile such as `adaq-python@1`; the initial M12 Profile resolves to a CI-qualified CPython `3.12.x` Artifact and exact platform hash rather than the newest locally available version. Compatible Projects share the content-addressed Runtime but keep Dependency-Lock-specific environments isolated. Environment preparation coalesces the exact Runtime-and-Lock identity, serializes setup separately from the Research Queue, builds in private staging, and atomically publishes only fully verified output; Failed or Cancelled attempts leave no executable partial environment, and Retry creates a new identity. New Profiles create new identities and never silently change an existing Project Revision or historical Attempt; an old Artifact may be downloaded again while supported, and a security-disabled Runtime leaves evidence readable but cannot execute. Settings exposes Runtime, wheelhouse, and environment disk use and permits explicit eviction of inactive cached bytes without deleting historical identities; rerunning reconstructs them. Missing, cancelled, failed, evicted, or offline setup disables only Python features and leaves the rest of ADAQ usable; V1 provides a clear Retry path but no custom interpreter path or offline Runtime import.
