# Keep Python Runner results staged and Host-authoritative

ADAQ launches one Python Research Runner per Attempt and connects it to a random `127.0.0.1` port with a one-time token and an exact Protocol, SDK, Revision, and Attempt handshake. Bounded control messages use length-prefixed canonical JSON, typed tables use Arrow IPC, large artifacts use private Attempt-scoped staged files with declared hashes, and stdout or stderr are logs rather than protocol channels. The Runner cannot write authoritative SQLite records or final Dataset locations: the Host validates identity, ordering, schema, availability, finite values, Decimal rules, limits, and hashes before atomically publishing complete results. Failed or Cancelled Factor and Strategy Attempts publish no partial result; a Model may retain only declared, capped diagnostic checkpoints that remain non-deployable. Cancel first requests cooperative shutdown, then terminates the process tree after a bounded grace period, ignores late results, and records Cancelled only after exit and staging isolation; stale Running Attempts recovered after an app restart become Failed with an Interrupted reason, and Retry always creates a new Attempt. A versioned Host resource policy caps wall time, memory, threads, input dimensions, protocol traffic, artifacts, checkpoints, logs, and Strategy decision deadlines, while exact platform values are set from benchmarks.
