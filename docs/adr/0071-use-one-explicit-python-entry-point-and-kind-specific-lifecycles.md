# Use one explicit Python entry point and kind-specific lifecycles

Every Python Research Project Manifest names one exact `module:function` entry point whose zero-argument `create_project()` is imported and called only after the User trusts that Revision. The Runner performs no file, class, decorator, or framework discovery, and the returned SDK object must match the declared Kind and Mode; parameters, Seed, data, progress, and diagnostics arrive only through later typed Context calls. A Portable Factor or Strategy defines one canonical Host-owned Definition without Dataset access. An Imperative Factor evaluates scope-correct batches within Host-declared Continuous Bar Segments and is recreated at Bar Gaps. A Model fits with only Train and Validation inputs and labels, is persisted and reloaded through its registered Adapter, then predicts Validation or Test Forecasts while the Host withholds Test labels and computes final metrics. An Imperative Strategy starts one causal Session and receives exactly one ordered Decision Batch and current Portfolio State at a time, returning only one complete Target before Host-owned Risk, Execution, and state updates; no decision calls are pipelined or allowed to prefetch future input, and a Bar Gap recreates the Project and Session. Supported mutable causal state lives only in returned Project, evaluator, or Session objects and ends at the Host-declared segment boundary; mutable module globals, ambient disk caches, and cross-Attempt state are outside the contract. Context exposes only bounded structured progress and diagnostics, stdout and stderr remain capped logs, and exceptions, missing batches, missed deadlines, or invalid outputs fail the Attempt without publishing partial results or falling back to earlier evidence.
