# Make Python tuning Host-owned and repeatability-gated

ADAQ freezes each Python Project's portable ordered Input Slot contracts in its Manifest, binds them to exact local Snapshot, Dataset, Universe, Factor, Signal, and other evidence identities only when a Lab Run is created, and records those bindings in every Attempt; Project code cannot query a latest local object dynamically. V1 parameter search is only a single typed parameter set or a finite Host-expanded Cartesian Grid, with each combination registered as a separate Trial and Attempt under the existing kind-specific lineage and resource limits; script-owned Sweeps, Optuna, Bayesian search, and hidden multi-Trial results are excluded. Comparisons use an explicit Selection Window, after which an immutable Parameter Selection Decision freezes one candidate before a disjoint Final Evaluation whose labels remain Host-only where applicable. Using a completed Final result to modify or select another candidate creates derived lineage and Overlapping rather than falsely Out-of-sample evidence.

Before importing a Project, the Runner sets the Attempt Seed for `PYTHONHASHSEED` and registered Python, NumPy, and framework random sources and applies Host thread limits; SDK Context supplies frozen event times but no current wall clock. Supported mutable causal state lives only in returned Project, evaluator, or Strategy Session objects and ends at Host segment boundaries. A Python Repeatability Report reruns the same Revision, Environment, Input bindings, parameters, and Seed in a fresh process and across permitted Batch partitions: Factor and Strategy require exact equality, while a registered Model Deployment Profile may declare bounded numeric tolerance. Unverified or Divergent exploratory results remain inspectable but cannot pass Promotion, Component Generation, or Runtime Qualification.

The bundled tutorial makes the boundary concrete with fixed finite Grids: Factor `lookback={5,20,60}` with default 20, Qlib Ridge `alpha={0.1,1,10}`, and Strategy `forecast-weight={0.5,0.7}`, `top-n={3,5}`, and `cash-reserve={0,0.1}` with defaults 0.7, 3, and 0.1. Defaults are tutorial inputs rather than universal recommendations. Its 180 sessions split into Train 1–100, Purge 101–105, Selection Validation 106–140, Embargo 141–145, and Final Evaluation 146–180; a five-session Target crossing a boundary is Unavailable rather than shifted. The guided flow requires explicit Parameter Selection Decisions before held-out evaluation and an explicit Research Validated Factor Promotion Decision before the Model may bind the Factor.
