# Start Qlib with a Host-fed Ridge Adapter and data-only Artifact

M12's first registered Qlib path supports only `LinearModel` in Ridge mode and exactly one Continuous Forecast Target, horizon, and Forecast Signal per Python Model Project. The `adaq.qlib` Dataset Bridge converts Host-authorized Arrow partitions into stable read-only `(datetime, instrument)` tables and implements only the `DatasetH.prepare()` surface required for `train`, `valid`, and feature-only `test`; it does not initialize a Qlib data Provider, download data, construct Alpha158 inputs, or access a network. Host-owned transformations fit only on Train and are frozen as Fitted Transformation Artifacts before being applied unchanged to Validation and Test. Script-owned preprocessing remains useful exploration but Research Only until it has an explicit supported operation and Artifact schema.

After Qlib fitting, the Adapter extracts canonical `adaq:linear-model@1` data: ordered Input Slots, finite coefficients, intercept, numeric representation, the exact transformation identity, Forecast contract, and Adapter provenance. It reloads that schema before producing Forecasts, so Python pickle and executable object graphs are neither authoritative Model Artifacts nor eligible Project Archive, Component, or Marketplace contents. M14's first Model Exporter converts only this Linear Model Artifact into a WASI Model Component and requires Forecast equivalence against the Qlib source result. Generic Qlib-to-WASM and Qlib-to-ONNX conversion are not promised; ONNX and Local Qlib Paper remain named profiles that require a future registered Adapter and demonstrated need.
