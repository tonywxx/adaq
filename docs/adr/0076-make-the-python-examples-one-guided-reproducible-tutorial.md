# Make the Python examples one guided reproducible tutorial

ADAQ bundles three independently valid Apache-2.0 Projects under `examples/python/`: `py-factor-cross-sectional-momentum`, `py-model-qlib-ridge-return`, and `py-strategy-top-n-forecast`. Factor and Strategy depend only on the pinned Python Research SDK; Model uses only the signed base Wheelhouse's SDK, Arrow, NumPy, and Qlib Ridge Adapter. None downloads data, accesses a network, or adds a Project-specific wheel. One Host-owned `python-tutorial-a-share@1` fixture under `src-tauri/fixtures/python-tutorial/` contains a manifest, Instrument Master, Calendar, and daily Bar JSON for 12 clearly fictional A-share-like Instruments over 180 Trading Sessions and stays outside Project Archives.

The fixed windows are Train sessions 1–100, Purge 101–105, Selection Validation 106–140, Embargo 141–145, and Final Evaluation 146–180; a five-session Forecast Target crossing a boundary is Unavailable. The finite tutorial Grids are Factor `lookback={5,20,60}` with default 20, Ridge `alpha={0.1,1,10}`, and Strategy `forecast-weight={0.5,0.7}`, `top-n={3,5}`, and `cash-reserve={0,0.1}` with defaults 0.7, 3, and 0.1. These values demonstrate the workflow and are not claims of optimality. Golden evidence requires exact Factor rows, identities, Unavailable states, Strategy ordering, and Portfolio Targets. Ridge coefficients and Forecasts use the Adapter's strict finite tolerance; the fixture preserves score separation so allowed numeric variation cannot change Top-N and final Targets remain exact.

Run Python Tutorial is a guided flow, not an unattended promotion pipeline. It first shows the three exact Revisions, entry points, Locks, required download and disk use, and trusted-code warning; one User confirmation may record three separate exact-Revision Trust Decisions, while a later change re-prompts only for that Project. The flow runs and displays Factor evaluation, then waits for the User's Parameter Selection and Research Validated Promotion Decisions; it similarly waits for the Model and Strategy Parameter Selection Decisions before their held-out evaluation and Backtest steps. Mechanical validation, Environment preparation, execution, and navigation may be automated, but User-owned evidence decisions never are.

Each Project includes executable English and Simplified Chinese instructions for Create from Example, Validate, Prepare, Trust, Run, tune, inspect evidence, and troubleshoot, with one bilingual top-level tutorial linking the chain. CI validates documented paths, parameters, and expected structures. Pull requests run the complete no-network chain on Linux x86_64 plus fast Manifest, Archive, and SDK contract checks on all three platforms; `main`, Release, and manual workflows run Runtime preparation, the full chain, Golden evidence, and cancellation, trust, Lock, and invalid-output failures on macOS ARM64, Windows x86_64, and Linux x86_64. Each M12, M13, and M14 delivery slice records one all-platform green run before acceptance. Any displayed return is labelled Synthetic Demonstration and never presented as expected profitability.
